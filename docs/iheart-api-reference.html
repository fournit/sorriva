iHeartRADIO API Reference

Undocumented iHeart API endpoints used in Passione products. Validated July 2026. No official API documentation exists — all findings are from reverse engineering.

Unofficial API: iHeart has no public API. These endpoints are reverse-engineered from the iHeart mobile app and web player. They may change without notice. Test before shipping.

Overview

iHeart exposes two API versions: v2 (older, more data) and v3 (newer, some endpoints return 410 for digital stations). The base URL is https://us.api.iheart.com.

API VersionBase URLStatus
v2https://us.api.iheart.com/api/v2/Active — use this for station info and stream URLs
v3https://us.api.iheart.com/api/v3/Partial — now-playing endpoint returns 410 for digital stations

Authentication

No API key required for the endpoints used. However, server-side calls (from Mac Mini, not iPhone) return 403 Forbidden. Must use a mobile User-Agent header.

Server-side calls fail with 403. Always use a mobile User-Agent. This affects any server-side code (Node, Python, Swift on Mac) calling iHeart APIs.
// Required User-Agent for all iHeart API calls: "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1" // iOS URLSession uses the device's User-Agent automatically — no header needed on device // Server-side Swift/Python/Node must set this header explicitly

Station IDs

Each iHeart station has a numeric stream ID. Extract from iHeart URLs:

https://www.iheart.com/live/yacht-rock-radio-8681/ → stream ID: 8681 https://www.iheart.com/live/lost-80s-7934/ → stream ID: 7934 https://www.iheart.com/live/alternative-rewind-6950/ → stream ID: 6950 https://www.iheart.com/live/the-valley-80s-10252/ → stream ID: 10252 https://www.iheart.com/live/iheart80s-5060/ → stream ID: 5060 // Pattern: last segment before trailing slash, after the last hyphen // URL slug: {name}-{id}

Sonos also encodes the stream ID in the HLS URI it uses internally:

// From GetMediaInfo CurrentURI on a Sonos playing iHeart: x-sonosapi-stream:live_stations.8681?sid=6&flags=8232&sn=3 ^^^^ stream ID embedded here

Station Info Endpoint

GET https://us.api.iheart.com/api/v2/content/liveStations/{streamID} Example: GET https://us.api.iheart.com/api/v2/content/liveStations/8681

Stream URLs

The streams object in the station info response contains multiple URL formats:

KeyFormatUse
hls_streamhttp://stream.revma.ihrhls.com/zc{id}/hls.m3u8Use this for Sonos — HTTP required for hls-radio:// prefix
secure_hls_streamhttps://stream.revma.ihrhls.com/zc{id}/hls.m3u8HTTPS — does NOT work with Sonos hls-radio:// prefix
shoutcast_streamhttp://stream.revma.ihrhls.com/zc{id}Fallback — non-HLS, lower quality
secure_shoutcast_streamhttps://stream.revma.ihrhls.com/zc{id}HTTPS shoutcast — avoid
Always use hls_stream (HTTP) for Sonos playback. The hls-radio:// prefix that Sonos requires for HLS streams does not work with HTTPS URLs. Prepend hls-radio:// to the HTTP HLS URL.
// Correct Sonos stream URL construction: let hlsURL = station["hls_stream"] // "http://stream.revma.ihrhls.com/zc8681/hls.m3u8" let sonosURI = "hls-radio://\(hlsURL)" // → "hls-radio://http://stream.revma.ihrhls.com/zc8681/hls.m3u8"

Now Playing Track

Not available for iHeart digital-only stations. Track metadata is embedded in the HLS audio stream — it cannot be retrieved externally without actively decoding the stream.

v3 currentTrackMeta (tested, does not work for digital stations)

GET https://us.api.iheart.com/api/v3/live-meta/stream/{streamID}/currentTrackMeta Response for digital stations: {"code": 410, "reason": ["No meta data for {streamID}"], "fields": []} // 410 = Gone — endpoint exists but no data for digital-only stations // Terrestrial broadcast stations may return data — not tested

Where track data actually comes from

When Sonos plays an iHeart station, track metadata arrives via HLS stream metadata tags embedded in the audio stream. Sonos parses these and exposes them via GetPositionInfo in the r:streamContent field — but only while the stream is actively playing on a zone.

// Track metadata flow: iHeart HLS stream → embedded ID3 tags → Sonos parses → GetPositionInfo r:streamContent ↑ only accessible while playing

Station Logos

Logo URLs from the API are in iHeart's CDN format and can be used directly:

// Example logo URLs: https://i.iheart.com/v3/re/new_assets/5f5844d8a8e92688d3560ef4 // Yacht Rock Radio https://i.iheart.com/v3/re/assets.streams/651c7324a8732d6bdd71dccc // Lost 80s // These are stable — safe to cache in SQLite // No size parameters needed — returns full resolution // Pre-warm URLCache on app launch for instant display

Station Catalog Strategy

Since iHeart has no public search API without authentication, the recommended approach for Passione products is:

  • Hardcode a curated catalog of station IDs (extracted from iHeart URLs)
  • Fetch metadata (name, logo, stream URL) from the v2 API on first launch
  • Cache everything in SQLite — logo URLs, stream URLs, names
  • Pre-warm image cache on launch for instant display
  • Future: allow user to add stations by pasting iHeart URLs
