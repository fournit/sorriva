Sonos UPnP Reference

Complete reference for Sonos UPnP/SOAP APIs used in Passione products. Covers S2 firmware. Validated against live Sonos Era 100, Era 300, Arc Ultra, Roam hardware.

Hard-won knowledge: This document captures findings from building Sorriva (July 2026). Several approaches that should work per documentation fail on S2 firmware. Read the ⚠️ warnings carefully before implementing.

Architecture Overview

Sonos speakers expose a UPnP/SOAP control interface on port 1400. All household management, transport control, volume, EQ, and grouping operations are available via SOAP calls to individual speaker endpoints. No cloud dependency required for local control.

Each speaker is a UPnP device. The household topology (which speakers exist, which are grouped) is available from any single speaker via GetZoneGroupState. You don't need to query each speaker individually.

Zone Topology

GetZoneGroupState — Single Call, Full Household

Key insight: One SOAP call to any speaker returns the complete household topology — all zones, groups, coordinators, satellites, and IdleState. No need to query each speaker.
POST http://{any_host}:1400/ZoneGroupTopology/Control SOAPACTION: "urn:schemas-upnp-org:service:ZoneGroupTopology:1#GetZoneGroupState" Body: <u:GetZoneGroupState xmlns:u="urn:schemas-upnp-org:service:ZoneGroupTopology:1"/>

Response Structure

<ZoneGroups> <ZoneGroup Coordinator="RINCON_74CA60612AE901400" ID="RINCON_74CA60612AE901400:3428880515"> <ZoneGroupMember UUID="RINCON_74CA60612AE901400" ZoneName="Living Room" Location="http://192.168.1.219:1400/xml/device_description.xml" Invisible="0" IdleState="0" /> <ZoneGroupMember UUID="RINCON_C43875D79AC201400" ZoneName="Sub 4" Invisible="1" <!-- satellite — filter these out --> /> </ZoneGroup> <ZoneGroup Coordinator="RINCON_804AF29C40B601400" ID="RINCON_804AF29C40B601400:xxx"> <ZoneGroupMember UUID="RINCON_804AF29C40B601400" ZoneName="Master Bath" .../> <ZoneGroupMember UUID="RINCON_804AF29971CC01400" ZoneName="Master Bedroom" .../> </ZoneGroup> </ZoneGroups>

ZoneGroup/@CoordinatorRINCON UUID of the coordinator for this playback group

IdleState vs TransportInfo: The Arc Ultra reports PLAYING via GetTransportInfo even when the TV is off (HDMI ARC stays active). Use IdleState="1" from topology to correctly detect TV-off state. Refresh topology every 15 seconds to keep IdleState current.

GetPositionInfo — Current Track

SOAPACTION: "urn:schemas-upnp-org:service:AVTransport:1#GetPositionInfo" → Contains r:streamContent with pipe-delimited track metadata: "TITLE {track} | ARTIST {artist} | ALBUM {album} | ..." → Also contains RelTimePosition (elapsed) and TrackDuration

Zone Grouping

S2 Firmware Critical: The widely-documented x-rincon:// (double slash) URI format fails with error 501 on S2 firmware. Use x-rincon: (single colon). This took significant research to discover.

Joining a Playback Group

Send SetAVTransportURI to the member's host with x-rincon:{coordinatorUUID} as the CurrentURI.

POST http://{MEMBER_HOST}:1400/MediaRenderer/AVTransport/Control SOAPACTION: "urn:schemas-upnp-org:service:AVTransport:1#SetAVTransportURI" Body: <u:SetAVTransportURI> <InstanceID>0</InstanceID> <CurrentURI>x-rincon:RINCON_74CA60612AE901400</CurrentURI> <!-- coordinator UUID --> <CurrentURIMetaData></CurrentURIMetaData> </u:SetAVTransportURI> → Returns SetAVTransportURIResponse (empty = success)
What doesn't work on S2:
  • x-rincon://RINCON_XXX (double slash) → Error 501
  • GroupManagement:1 AddMember → adds rendering member only, NOT playback group
  • BecomeGroupCoordinator → requires exact current group state parameters
  • BecomeGroupCoordinatorAndSource → same issue, error 800

Leaving a Group (Standalone)

Send BecomeCoordinatorOfStandaloneGroup to the member's host.

POST http://{MEMBER_HOST}:1400/MediaRenderer/AVTransport/Control SOAPACTION: "urn:schemas-upnp-org:service:AVTransport:1#BecomeCoordinatorOfStandaloneGroup" Body: <u:BecomeCoordinatorOfStandaloneGroup> <InstanceID>0</InstanceID> </u:BecomeCoordinatorOfStandaloneGroup>

Hardware Bonds — Never Touch

Stereo pairs, Arc+Sub configurations, and HT satellite bonds are firmware-level and invisible in the topology (Invisible="1"). They appear as a single coordinator zone. Never attempt to break these — only playback groups are user-manageable.

Track Metadata

GetPositionInfo — r:streamContent

SOAPACTION: "urn:schemas-upnp-org:service:AVTransport:1#GetPositionInfo" → Response contains r:streamContent (pipe-delimited): "TITLE Saturday In The Park|ARTIST Chicago|ALBUM Greatest Hits|..." // Parse: for part in content.components(separatedBy: "|") { if part.hasPrefix("TITLE ") { track = String(part.dropFirst(6)) } if part.hasPrefix("ARTIST ") { artist = String(part.dropFirst(7)) } }
Track metadata availability: Only available when zone is actively streaming. iHeart digital-only stations (HLS) do not expose now-playing via any public API — the data is embedded in the audio stream and parsed by Sonos. No external API equivalent exists for idle zones.

DIDL-Lite Metadata

Always include station name and art URL in metadata — Sonos stores this and returns it via GetMediaInfo. Without it, station name is lost after playback.

// DIDL-Lite must be XML-entity-encoded when placed inside the SOAP body: let didl = "<DIDL-Lite xmlns:dc="http://purl.org/dc/elements/1.1/" " + "xmlns:upnp="urn:schemas-upnp-org:metadata-1-0/upnp/" " + "xmlns="urn:schemas-upnp-org:metadata-1-0/DIDL-Lite/">" + "<item id="-1" parentID="-1" restricted="true">" + "<dc:title>{stationName}</dc:title>" + "<upnp:albumArtURI>{artURL}</upnp:albumArtURI>" + "<upnp:class>object.item.audioItem.audioBroadcast</upnp:class>" + "</item></DIDL-Lite>"

Local File Playback

Sonos can play audio files served over HTTP via SetAVTransportURI. This is how third-party apps (Roon, Sorriva) stream local library files to Sonos without the Sonos app's NAS library feature.

NAS library feature removed: The current Sonos app (post May 2024) removed NAS library configuration entirely. x-file-cifs:// URIs cannot be used without pre-registered credentials, and there is no documented way to register credentials programmatically. Use HTTP serving instead.

URI Format

Serve the audio file over HTTP from a device on the local network and pass the URL as CurrentURI:

http://[server-ip]:[port]/track/[id].flac
File extension required — Error 714: Sonos S2 returns UPnP error 714 ("Illegal MIME type") if the URI does not end with a recognised audio file extension (.flac, .mp3, .m4a, .wav, .aiff). The server-side handler must strip the extension before processing the request. Plain UUIDs without extensions are rejected.

DIDL-Lite for Local Tracks — musicTrack class

Use object.item.audioItem.musicTrack for local files — not object.item.audioItem.audioBroadcast which is for radio streams. The metadata goes in CurrentURIMetaData as XML-entity-encoded DIDL-Lite.

<DIDL-Lite xmlns:dc="http://purl.org/dc/elements/1.1/" xmlns:upnp="urn:schemas-upnp-org:metadata-1-0/upnp/" xmlns="urn:schemas-upnp-org:metadata-1-0/DIDL-Lite/"> <item id="-1" parentID="-1" restricted="true"> <dc:title>Never Let Me Down Again</dc:title> <dc:creator>Depeche Mode</dc:creator> <upnp:album>Remixes 81-04</upnp:album> <upnp:duration>0:09:14</upnp:duration> <upnp:class>object.item.audioItem.musicTrack</upnp:class> </item> </DIDL-Lite>

When embedded in a SOAP body, the DIDL-Lite must be XML-entity-encoded (&lt;, &gt;, &quot;).

SetAVTransportURI SOAP call for local files

POST http://{host}:1400/MediaRenderer/AVTransport/Control Content-Type: text/xml; charset=utf-8 SOAPACTION: "urn:schemas-upnp-org:service:AVTransport:1#SetAVTransportURI" <s:Envelope xmlns:s="http://schemas.xmlsoap.org/soap/envelope/" s:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/"> <s:Body> <u:SetAVTransportURI xmlns:u="urn:schemas-upnp-org:service:AVTransport:1"> <InstanceID>0</InstanceID> <CurrentURI>http://192.168.1.205:8080/track/83C137BC-4010.flac</CurrentURI> <CurrentURIMetaData>[entity-encoded DIDL-Lite]</CurrentURIMetaData> </u:SetAVTransportURI> </s:Body> </s:Envelope>

Follow immediately with a Play transport action (see Transport Control section).

HTTP server requirements

  • Must be reachable from Sonos speaker on the local network (same subnet)
  • Must respond with correct Content-Type header (audio/flac, audio/mpeg, etc.)
  • Must respond with Content-Length — Sonos sends Connection: close and expects the full content length declared upfront
  • Must support Accept-Ranges: bytes for seeking
  • Sonos sends Connection: close on initial request — does not use keep-alive for file fetching

Sorriva implementation notes

  • HTTP server: NWListener (native Network framework) on port 8080
  • SMB reads: 1MB chunks with fresh SMBClient per chunk — required for UNAS Pro which drops sessions after 2 sequential reads
  • Backpressure: Each chunk send awaits .contentProcessed before reading next SMB chunk
  • Background audio: AVAudioSession .playback with .mixWithOthers keeps iOS process alive when screen locks
  • See sorriva-local-playback-arch.html for full architecture details
